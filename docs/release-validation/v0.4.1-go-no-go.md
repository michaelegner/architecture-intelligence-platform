## Known limitations (`KNOWN_LIMITATION`, not release blockers)

- Direct dependencies only — no transitive dependency traversal.
- Current state only — no historical/point-in-time snapshots, no snapshot diffing.
- No generic Cypher/graph query surface through any tool.
- MCP is exposed for a local/trusted-network posture — not hardened for direct public-internet
  exposure, no authentication/authorization, no multi-tenancy.
- Whole-graph read cost grows with total graph/evidence size — measured and committed
  reproducibly (this release), not remediated. No snapshot cache or retention policy exists yet —
  [ADR 0011](../adr/0011-snapshot-identity-read-cost.md)/[ADR 0012](../adr/0012-observed-evidence-retention.md)
  remain `Proposed`. This is an explicit, bounded, known limitation, not a blocker (spec §29).
- No topic/pub-sub (Kafka-style) messaging family — deliberate, per
  [ADR 0013](../adr/0013-no-topic-family-without-guards.md).
- All `v0.4.0` limitations still apply unchanged: gRPC/protobuf calls and Kafka topic/subscription
  semantics (Quarkus) unsupported; PostgreSQL/database dependencies (Airflow) unsupported; Airflow
  Execution API caller identity unresolved by design; Airflow runtime-role/Celery messaging
  identity unresolved, deferred; a legacy OpenTelemetry messaging-attribute recognition gap
  (Quarkus) insufficient evidence, deferred.
- Pre-1.0: Canonical Model, REST/MCP API surface, Graph Schema, Adapter SPI, and configuration
  format are not yet guaranteed stable.

None represents an incorrect supported claim.
