## What the release changed

Two bounded fixes and no new semantics, schema, claim type or MCP tool ([notes](v0.6.3-release-notes.md)):
- `POST /v1/traces` ingests in a worker thread, still one batch at a time behind a lock.
- A source holding an integer outside RFC 8785's safe range is rejected (`REJECTED_INVALID`,
  `DOCUMENT_PARSE_INVALID`) instead of aborting `POST /api/import`; the run stays `PARTIAL` and commits nothing
  (spec D4, and the sentence the spec required in the release notes).

## Notes

  agree, the absolute seconds depend on the machine. The notes were published as they were; the readiness comment offered rewording them as the alternative.

  is the one recorded on #504.

  out-of-range integer still makes the discovery run `PARTIAL`.
