# v0.8.0 — Hosted binding-picture record

Governing: the [v0.8 specification](../specifications/0.8.0/specification.md) D11 (the hosted profile enables
`experimental.binding-picture`) and D19 (the hosted redeploy is not part of I4). This is a post-release deployment
under those decisions. It changes no AIP code. The [v0.8.0 release notes](v0.8.0-release-notes.md) stay as published.

The public read-only instance serves the frozen v0.8 Sokol111 C1 package. This is a **frozen local Kafka observation
at its capture time** plus authored declarations and a generated EventCatalog. It is not live consumption and not
a complete view of Sokol111.

## Hosted switch (owner, 2026-10-30)

The compose change is five lines:
- `CONFIG_PATH`;
- the two read-only mounts;
- the Neo4j volume line;
- the new volume declaration.

Backups of the previous compose file and `.env` are kept on the server, together with the v0.7.2 package directory.

Before the switch, the same configuration ran on the same image digest locally. Every check that applies passed
(`--local-app`), and that answer is byte-identical to the hosted one.

One owner-side step failed and is disclosed here. The switch script followed the first import with a REST
binding-picture call whose body also carried `mode`. The REST route supplies `mode` itself, and the closed schema
refused the body with `422`. The import before that call had already succeeded. The checks below use MCP from outside.

without credentials. The rate-limit check was not enforced (no threshold given).

The binding-picture comparison covers these fields of every row:
- `broker_id`, `topic_name`, `consumer_service_id`;
- `crossing`, `status`, `reason`;
- `cross_broker_producers`.

The constants are pinned to [`c1-expected.json`](../specifications/0.8.0/i2-vectors/c1-expected.json) by
`tests/unit/test_pitstop_demo_public_edge.py`.

After review, the check became stricter, per row. Every row must be captured at T and have its own attachment and
mapping refs. Promise refs must appear exactly on the two `PROMISED_AND_OBSERVED` rows. The stricter check also
passed against the live endpoint (15:54:06Z), with no redeploy.

**Determinism.** The full query answer, serialized with sorted keys, has sha256 `9c97b871…945c81` and snapshot
`aip:snapshot:v1:7f171aea…`. It was fetched from outside after the first import and again after the second import.
It is byte-identical both times, and also byte-identical to the local rehearsal.

## Rollback

Restore the two backups and recreate `neo4j` and `architecture-intelligence` only. This returns to v0.7.2 on the
untouched v0.7.2 graph volume, with no re-import. The old volume and package stay on the server until the owner
removes them.
