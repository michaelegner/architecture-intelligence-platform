# AIP v0.8.1 — Server-Provided Agent Skills

**Status: release candidate: not a published release.** Links in this file are relative to the
repository; the published release body pins them to the release tag.

v0.8.1 is an **interoperability patch release**. It adds no architecture question, canonical entity
or relation, public answer schema or MCP tool, and it changes no tool answer. The seven tools (six
by default, plus the experimental `get_binding_picture` when its flag is on), their schemas and
their answers are unchanged from [v0.8.0](v0.8.0-release-notes.md)
([specification](../specifications/0.8.1/specification.md)).

## What changed

- **Agent skills served by the AIP MCP server.** Through the MCP Skills extension
  ([SEP-2640](https://modelcontextprotocol.io/seps/2640)), AIP serves skills that state how to read
  its answers. A skills-capable client gets the same reading rules as the tool contract it calls,
  from the same server version. There are two skills:
  - `aip-reading-answers`, always served: the observation context, the publisher's qualification,
    `evidence_refs` against `resolution_evidence_refs`, the snapshot retry, the distinctions of the
    other tools, the unknowns to report, and read-only use;
  - `aip-binding-picture`, served only with `experimental.binding-picture`: the modes, crossings,
    statuses and limits of `get_binding_picture`.

  Each skill is one static file. It contains no deployment-specific content. See
  [Skills](../mcp.md#skills-v081).
- **MCP protocol `2026-07-28`.** The Skills extension is defined for `2026-07-28`, and Claude Code
  requests skills only on that era ([I0 spike](../specifications/0.8.1/i0-protocol-spike-record.md)).
  `/mcp` now also serves it ([ADR 0018](../adr/0018-admit-mcp-2026-07-28.md), amending ADR 0016).
  The `2025-11-25` negotiated path is unchanged from v0.8.0: its `initialize`, `resources/list` and
  `tools/list` results are equal to v0.8.0's, and the skills are not reachable on it. Every tool
  gives the same answer on both eras.
- **`subscriptions/listen` is declined.** AIP does not serve it on either era, so `listChanged` and
  `subscribe` are advertised as `false`. AIP's tools and skills are static.
- **An ingress fix.** The `/mcp` guard now gives the server its own connection `receive` after it
  replays the request body. Before, a modern `subscriptions/listen` request would have blocked the
  server's event loop. This path was not reachable before v0.8.1.
- **Image and dependencies.** The base moves to `python:3.14.10-slim`, and the build-time `uv` to
  0.13.10, both pinned to their digests. The new `uv` bundles `rustls` 0.23.46, which fixes the four
  `rustls` advisories that v0.8.0 accepted. The locked `fastapi`, `starlette`, `pydantic`, `openai`
  and OpenTelemetry packages move to newer versions (see the [CHANGELOG](../../CHANGELOG.md)). The
  MCP SDK stays at `mcp==2.3.0`.

Product, Producer and MCP server version become **0.8.1**. Existing configurations and the published
schemas are unchanged.

## Client support

- Claude Code **2.1.332 or later** finds and loads the AIP skills. Its MCP-server skills are a beta
  feature. The Pitstop Claude Code plugin keeps its own skill, unchanged.
- A client that negotiates `2025-11-25` gets exactly the v0.8.0 behaviour and no skills.

## Known limitations

- Claude Code's MCP-server skills are in beta; their behaviour can change in a later Claude Code
  release.
- The skill text is a review responsibility. Tests check only that each tool name and each code
  that a skill names exists.
