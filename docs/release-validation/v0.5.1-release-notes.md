# v0.5.1 Release Notes

**Status: release candidate — not a published release.** Links in this file are relative to the
repository; the published release body pins them to the release tag.

## Release story

**v0.5.1 shows how a developer and their coding agent get the architecture context for a real
change, without reconstructing it themselves.**

It adds a ready-to-run demo over [Quarkus Super Heroes](https://github.com/quarkusio/quarkus-super-heroes),
one of the two real systems v0.5.0 was qualified against. The demo is built around one task: *before
changing image narration in `rest-fights`, what do I need to know?* One command replays the
already-qualified evidence, and AIP answers with operation-level dependencies, runtime
qualifications, deployment identity, event publication and the evidence behind each claim. What it
cannot establish stays explicit instead of guessed.

v0.5.1 adds no Architecture Knowledge semantics, source families or MCP tools.

## What's new

- **One-command demo:** `examples/quarkus-super-heroes-demo/run.sh`. It needs Docker and `curl`;
  there is no Quarkus build, Kafka, cluster or model key. It:
  - starts AIP, Neo4j and an OpenTelemetry Collector;
  - imports the frozen v0.5.0 dossier inputs unmodified;
  - replays a timestamp-frozen observation window once, then stops the Collector;
  - checks the real `rest-fights` answer against the frozen evidence, and fails visibly if it
    differs;
  - prints a ready-to-copy agent prompt.

  `run.sh --down` removes everything.
- **What the answer shows:**
  - seven operation-level `CALLS`: three `CONFIRMED`, and four `NOT_OBSERVED_IN_WINDOW`
    (not exercised, which does not mean unused);
  - a `DEPLOYED_AS` resolved only through the configured mapping;
  - for the same-named `rest-narration` Deployment, no deployment claim at all, because a matching
    name never resolves an identity.
- **Messaging through an operator-authored overlay.** Quarkus Super Heroes ships no AsyncAPI, so the
  demo adds a small, disclosed AsyncAPI overlay for the Kafka topic `fights`:
  - AIP reports `rest-fights` `PUBLISHES_TO` Topic `fights` from that declaration, not confirmed at
    runtime;
  - its consumer stays unresolved: the answer is `PARTIAL`, with one `UNRESOLVED_IDENTITY`
    limitation;
  - a Kafka consumer group never becomes a Subscription.
- **Question-by-question walkthrough** (`walkthrough.md`): eight task questions, each with the MCP
  and REST call and the real answer. AIP results, dossier context and agent suggestions are kept
  visibly apart.
- **Recorded agent conversation** (`conversation-claude-code.md`): a real Claude Code conversation
  that uses only the three AIP MCP tools, checked question by question. Editorial notes mark two
  suggestions that the demo cannot follow or that the evidence rules do not support.
- **CI coverage:**
  - a smoke test in the `demo-e2e` job runs the real `run.sh`, re-checks the answer over MCP against
    the published v0.5 schemas, and drills down to the evidence at the same snapshot;
  - `run.sh` is covered by shellcheck.

## What changed for integrators

Nothing. The public surface is the v0.5.0 surface:
- exactly three read-only MCP tools;
- `schema_version` `"0.5"`;
- the same REST routes.

Only `producer.version` reports `0.5.1`.

## Known limitations

- **The demo is a replay, not a live system.** Its runtime evidence is a transcription of the v0.5.0
  qualified observations: one fight in a 7-second window. It contains no gRPC or Kafka spans, and it
  cannot observe new calls.
- **The messaging overlay is operator-authored** declaration evidence. It is not upstream-supplied
  and not qualification evidence.
- **Not in AIP's answer.** The gRPC call from `rest-fights` to `grpc-locations` and Kafka runtime
  observation stay unsupported, as in v0.5.0. The demo labels the gRPC call as dossier context.
- **Observed behaviour (unchanged from v0.5.0):** a second source for an existing Service can
  replace its display name without a diagnostic. The demo avoids this by giving the overlay the
  existing names.
- **The recorded conversation is an example, not a client re-qualification.** The client matrix is
  still the v0.4.2 one.
- **Ports:** the demo uses ports 8000 and 4318, so it cannot run alongside the minimal demo.
