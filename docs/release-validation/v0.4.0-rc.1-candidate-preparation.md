`semantic_outputs_identical: true`. Only `candidate_sha` and the resulting `run_output_sha256`
(which embeds `producer.build_revision`) differ, since nothing under I3.4 touched anything this
evaluator exercises. Committed as its own evidence-only change per spec §9.1 ("candidate-bound
evaluation result" is an explicitly allowed evidence-only commit type) — no production, schema,
test, or evaluation-logic change.

## Version and lock consistency (spec §11)

### Finding confirmed

```text
pyproject.toml   [project].version = "0.3.0"
uv.lock          root project "architecture-intelligence-platform" version = "0.3.0"
```

Matches spec §4.1's entry observation exactly. No other file references the project's own current
version — `FastAPI()` is constructed with no `version=` kwarg (`app/main.py`); MCP `producer.version`
is a separate hardcoded constant already at `"0.4.0"` (spec §4.2), unaffected by this change.

### Fix applied

```diff
- version = "0.3.0"
+ version = "0.4.0"
```

in `pyproject.toml`, followed by `uv lock` to regenerate `uv.lock`. The resulting lock diff is
exactly one line:

```diff

+ version = "0.4.0"
```

in the root `architecture-intelligence-platform` package entry — `uv lock` reported `Resolved 65
packages` both before and after (unchanged package count), confirmed by a full `git diff uv.lock`
showing no other line changed. Dependency resolution is therefore unchanged; no justification note
is required (spec §11: "any third-party package/version/hash change SHALL be treated as dependency
mutation and explicitly justified").
