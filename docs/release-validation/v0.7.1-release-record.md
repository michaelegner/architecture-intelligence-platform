## What the release changed

A sixth read-only MCP tool, `get_destination_consumers`, with REST parity
([notes](v0.7.1-release-notes.md)). For one Kafka Topic in one broker and environment, it lists each
consumer group attached at capture time T. Each row carries its Service attribution from explicit
mapping evidence, and same-snapshot evidence refs. The answer is always `PARTIAL` with
`CAPTURE_SCOPE_LIMITED`, and attachment is not message processing. Qualification is in the
[I4 result record](../specifications/0.7.1/i4-result-record.md) (owner decision `CONTINUE`).

## Security dispositions (owner, 2026-10-21)

- **GHSA-6q48-6c7w-9gw2 (CRITICAL), `certifi 2026.6.17`.**
  - **Where:** pip's own bundled copy in the base image's system Python (`/usr/local/lib/python3.14/site-packages/pip/_vendor/certifi`, pip 26.2.1).
  - **Exposure:** AIP's runtime venv `/app/.venv` contains neither certifi nor pip, so AIP never reaches it. The published v0.7.0 image has the same finding; the advisory appeared after v0.7.0's release scan.
  - **Upstream fix:** pip 26.2.2 (2026-10-20) bundles certifi 2026.10.19.
- **DSA-6572-1 (severity UNKNOWN), `ca-certificates 20250419`.** It is fixed in `20250419+deb13u1`. Trivy reported it only in the uploaded code-scanning results; the HIGH/CRITICAL readiness scan doesn't include UNKNOWN-severity findings.
- **Decision:** both were accepted for v0.7.1. A follow-up patch removes pip from the runtime image and takes a newer base image.
- **The #611 wording:** the CHANGELOG and notes sentence on #611 ("the runtime image does not install it") refers to AIP's own `certifi` dependency, not to pip's bundled copy.
