## WP2 — Version and lock consistency (spec §10)

### Finding confirmed

```text
pyproject.toml   [project].version = "0.2.0"
uv.lock          root package "architecture-intelligence-platform" version = "0.2.0"
```

Both were still `0.2.0` at `v0.3.0-rc.1` (`9f95d48`), despite that tag being the `v0.3.0` release
candidate. Per spec §10, this is release-blocking: "the source archive and installed project
metadata are public release artifacts."

No other file references the project's own current version — `FastAPI()` is constructed with no
`version=` kwarg (`app/main.py`), so no running-application surface needed a corresponding change.
The single hit for `0.2.0` elsewhere in the tree (`evaluation/model.py`'s docstring, citing
`docs/specifications/0.2.0/`) is a historical iteration reference, not a project-version string, and
correctly retains its historical value per spec §10 ("historical changelog entries, old
specifications, and prior release-validation records SHALL retain their historical versions").

### Fix applied

```diff
- version = "0.2.0"
+ version = "0.3.0"
```

in `pyproject.toml`, followed by `uv lock` to regenerate `uv.lock`. The resulting lock diff is
exactly one line:

```diff
- version = "0.2.0"
+ version = "0.3.0"
```

in the root `architecture-intelligence-platform` package entry — `uv lock`'s own output confirmed
`Resolved 56 packages` both before and after (unchanged package count), and a direct `diff` of the
full lock file before/after shows no other line changed. Dependency resolution is therefore
unchanged; no justification note is required (spec §10: "dependency resolution unchanged unless
explicitly justified").
