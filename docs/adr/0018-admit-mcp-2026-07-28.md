# 18. Admit MCP protocol `2026-07-28` on `/mcp`

Status: Accepted — implemented in `v0.8.1` I1. It amends
[ADR 0016](0016-public-architecture-knowledge-adapters.md) **only** with respect to the protocol
eras that `/mcp` serves.

## Context

ADR 0016 made standard negotiated MCP (`initialize`, protocol `2025-11-25`) one of AIP's two
public adapters. Its ingress guard rejected every follow-up request whose `MCP-Protocol-Version`
header named the `2026-07-28` era, the era of the retired v0.4.x direct mode.

v0.8.1 serves agent skills through the MCP Skills extension
([SEP-2640](https://modelcontextprotocol.io/seps/2640)). The extension is defined for protocol
`2026-07-28` and later. The [I0 protocol spike](../specifications/0.8.1/i0-protocol-spike-record.md)
showed outcome B: Claude Code 2.1.332 requests skills only on `2026-07-28`. On `2025-11-25` it does
not request them, even when the server advertises the extension. The owner accepted outcome B as a
patch-release change (v0.8.1 spec D3), with two conditions: the `2025-11-25` path stays unchanged
(D8), and AIP declines `subscriptions/listen` (D9).

## Decision

1. **`/mcp` serves both eras.** The ingress guard (`app/mcp/guard.py`, now `McpIngressGuard`) no
   longer rejects a request that names `2026-07-28`. The pinned SDK (`mcp==2.3.0`) routes each
   request by its `MCP-Protocol-Version` header to its modern path or its negotiated path. The guard
   keeps only the 405 for non-POST methods and the 1 MiB body limit.
2. **The skills methods are modern only.** `skills/list` and `skills/get` are bound for
   `2026-07-28`. On `2025-11-25` they return `METHOD_NOT_FOUND`.
3. **The `2025-11-25` path is unchanged (D8).** A server middleware hides the skill resources on
   every non-modern request: `resources/list` leaves them out, and `resources/read` of a skill URI
   returns the SDK's unknown-resource error. The `initialize`, `resources/list` and `tools/list`
   results equal those of v0.8.0 apart from release-version metadata (`serverInfo.version`).
4. **AIP declines `subscriptions/listen` (D9).** `MCPServer(subscriptions=False)` leaves the method
   unserved on every era, so the advertised `listChanged` and `subscribe` values are false. AIP's
   tools and skills are static: it has no list-changed notification to deliver.
5. **No semantic change.** Every tool, its input and output schema, and every answer are the same on
   both eras. Only the transport envelope differs.

## Consequences

- A client that probes `server/discover` on `2026-07-28` is now served instead of falling back to
  `initialize`. A client that uses `initialize` gets exactly the v0.8.0 behaviour.
- The guard replays the buffered request body once and then gives the server's own `receive` to the
  SDK. The SDK's modern SSE path (used for a `subscriptions/listen` request) waits on `receive` for
  `http.disconnect`. A replay that returned the body again never suspended, so that wait would spin
  and block the event loop.
- Tests: `tests/unit/test_mcp_skills.py` covers `2026-07-28` discovery, the skills wire shape, the
  stored v0.8.0 `2025-11-25` results (`tests/fixtures/mcp_v080/`) and every tool on both eras.
  `tests/unit/test_mcp_discovery.py` checks that a modern follow-up is served, and
  `tests/unit/test_mcp_guard_body_limit.py` checks the body replay. Each guard test fails when its
  change is reverted.
- Each later SDK upgrade must keep both eras passing these tests.
