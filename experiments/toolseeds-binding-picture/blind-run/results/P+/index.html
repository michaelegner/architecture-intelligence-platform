Binding picture: Catalog Management on the Kafka broker (environment local)

Question
When moving Catalog Management (Catalog and Image) to Apache Kafka, which bindings are configured across the boundary and what is not established?
Boundary
Catalog Management = ecommerce-catalog-service + ecommerce-image-service. Defined by the task, not inferred from source. The provider's bounded context catalog-management lists the same two services as producers provider. Counterparts below are services that the inspected config/code connects to the selected side through Kafka.
Environment
local (k3d + Tilt + docker-compose). Production values were not inspected.
Scope
Only Kafka bindings (topics, consumer groups, DLQ, the broker endpoint) of the two services, in both directions. Not a full dependency map. gRPC/HTTP, MongoDB, S3 and imgproxy bindings are out of scope for this question.
Premise check
The services already use the Kafka protocol (Go client franz-go, E30). The broker running locally is Redpanda redpandadata/redpanda:v24.3.1 (E25), and the docs say Redpanda also runs in production (E28, doc only). So "moving to Apache Kafka" means changing the broker, not adopting messaging for the first time.
